# Velin Android

The native Android client is a Kotlin and Jetpack Compose application. It builds a debug APK, provides the initial dark Velin theme and `Home / Search / Library` navigation, implements QR-camera and manual pairing, and loads authenticated status, artist, album, track, and search data from the server.

## Requirements

- JDK 17
- Android SDK Platform 37.0
- Android SDK Build-Tools 36.0.0
- `ANDROID_HOME` pointing to the SDK

A system Gradle installation is not required; use the checked-in Gradle Wrapper.

## Commands

From this directory:

```sh
./gradlew assembleDebug
./gradlew testDebugUnitTest
./gradlew lintDebug
```

Or from the repository root:

```sh
make android-build
make android-test
make android-lint
```

The debug APK is written to `app/build/outputs/apk/debug/app-debug.apk`.

## Pairing

The pairing screen scans the strict JSON payload generated by the administration page (`server_url` and `code` only) using CameraX and the standalone ZXing decoder. Camera permission is requested only when scanning starts, the camera is optional, and manual entry remains available. Server URLs are normalized and restricted to HTTP(S) without embedded credentials, query strings, or fragments. Successful responses are size-bounded and parsed into server/device metadata. The bearer token and related connection data are encrypted with an AES-GCM key held by Android Keystore before being stored in private app preferences; the token is never displayed or placed in a URL.

Plain HTTP is enabled for trusted-LAN deployments and produces an in-app warning. Use HTTPS outside a trusted private network.

## Authenticated API

After pairing, a dedicated OkHttp client adds the stored bearer token through an interceptor; no HTTP logging interceptor is installed. JSON responses are size-bounded, model strings and page lengths are validated, and `401`/`403` responses lead the user back toward pairing without exposing credentials. Home loads server status and an initial library summary, Library shows the first artist/album/track pages, and Search queries the protected FTS endpoint.

## Current boundaries

Pagination beyond the first 50 items, detail screens, artwork loading, and Media3 playback remain to be implemented. Camera and Keystore behavior have not yet been exercised on a physical device because no ADB device was connected during validation.

Playback will use a Media3 `MediaSessionService`. Bearer authorization must be supplied through the Media3 data source and must never be placed in stream URLs or logs. Both FLAC and MP3 streams remain first-class inputs, and the client does not request transcoding.
